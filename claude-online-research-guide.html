1. How to read this guide

Good research with Claude has three parts. You pick the right tool. You write a clear request. You check each claim that matters.

The third part is the one most people skip. It is also the one with the best proof behind it. In a May 2026 test of five Claude models, the cited links worked 97 to 99 percent of the time. But the page behind the link backed up the claim only 52 to 77 percent of the time. Independent

The labels

Each fact in this guide has a label. The label tells you who said it.

Three limits of this guide
  • No outside group has tested the newest models (Opus 5.5 and Fable 5.2) for web research. All outside numbers come from older models.
  • Agents read the source pages. The author of this guide read their notes, not each page.
  • Claude changes fast. Treat each fact as true on 19 November 2026, not for all time.

2. Pick the type of research

Pick by the size of the question. Size means the number of tool calls the question needs. One tool call is one search or one page read.

The rule from Anthropic

Tool calls neededWhat to use
1 or 2A normal chat with web search.
3 or 4The rule does not cover this. Start in a normal chat. Move up if the answer is thin.
5 or moreResearch, also called deep research.

Vendor Help article of 2 June 2026. An agent read it through a summary, so the wording here is a paraphrase.

The API docs give a like guide: Single-fact queries typically use 1–3 searches; comparative or multientity research can use 10 or more. Vendor

How to guess the size

Count the things Claude must look up. Each one needs at least one search. Many need a page read too.

Three signs that a short question is large:

  • It names more than one thing, such as tools, countries or years.
  • It asks "why", "compare" or "should I".
  • The first answer has only one or two sources for a claim that matters.

A quick test: try to write the answer as one sentence with one source. If you can, it is a one-call question. If the answer needs a table, a list of trade-offs or the word "depends", it needs many calls.

Two examples

QuestionCallsWhy
"When was Python 3.13 released?"1One fact on one page. In Claude Code it can take 2, because search gives only titles and links there.
"Should I move my project from Python 3.11 to 3.13? It uses pandas, numpy and psycopg2."About 8Two Python versions, three libraries, and a hunt for known problems. Some results need a page read.

These call counts show the idea. Nobody measured them.

Size is not the only test

A question can need eight calls and still fit a normal prompt. Ask one more thing: do the parts depend on each other?

3. Steps for each type

A. Quick lookup

Use this for one fact. It works on all plans, free ones too. Vendor

  1. Ask in a normal chat.
  2. If Claude answers from memory, add the words "Search the web".
  3. Ask for the link and the date of the page.
  4. Open the page if the fact matters.

In the new claude.ai there is no search switch. The help page says: There's no web search toggle. Claude searches the web when it helps. The change is rolling out in steps, so your account may still show the switch. Vendor

All four current models have a knowledge cutoff of June 2026. A question about later events needs a search.

B. A multi-step prompt in one chat

Use this when the work is one line of thought, even with many calls. One agent does all of it in your chat.

  1. Write the request with the steps in section 5.
  2. Say how deep to go: one fact, a comparison or a broad survey.
  3. In Claude Code, set the effort with /effort. Anthropic names high for research.
  4. For a long task, ask Claude to keep a notes file. Each note needs the link, the date and an exact quote.
  5. If you do not want agents, say so: "Do not use subagents or the research skill."
  6. Check the claims with the steps in section 6.

What you give up: the agent that finds a claim also checks it. No fresh eyes look at the work.

D. The bundled /deep-research workflow in Claude Code

This is a script that runs many agents in the background. It is on all paid plans. On Pro, you turn workflows on in /config. It needs the WebSearch tool, so it does not work on Amazon Bedrock. Vendor

What the workflow does

The docs give four actions, in this order:

  1. Fan out. It searches your question from several angles.
  2. Fetch and cross-check. It reads the sources and compares them.
  3. Vote. It votes on each claim.
  4. Report. It writes one report with sources. Claims that failed the cross-check are left out.

If the check agents cannot test a claim, the report lists it as unverified. It does not count the claim as wrong. Vendor

The docs do not state the names of the phases, how many agents each phase starts, how many agents vote, or what counts as a pass. Not confirmed

One user saw a run queue 123 claims for a check. So there is a claim queue, then a check stage, then a final write-up. That is one run, not a spec. User report

Steps

  1. Run /model first. Ask Claude to use a smaller model for the search stages. If you skip this, each agent runs on your session model.
  2. Ask a narrow question first. Anthropic says to run the workflow on a small slice first.
  3. Start the run with /deep-research and your question.
  4. At the approval prompt, pick "View raw script" to read the real steps. Ctrl+G opens the script in your editor. You can then pick "No", and no agents start.
  5. Open /workflows to see each phase and the token use of each agent. Press x to stop a run that costs too much.
  6. To keep the script, select the run in /workflows and press s. You can then edit it and run it by name.
  7. Check the claims that matter. The vote lowers the risk. It does not remove it.

Vendor Dynamic workflows

The main risk is cost
  • A warning shows above 25 agents or 1.5 million planned tokens. It does not stop the run. Vendor
  • In July 2026, one user ran a broad question. The run started 111 agents and checked 25 of 123 claims. It hit the Max 5x limit in about 30 minutes, and no report came out. The user blamed agents that ran on the top model. User report
  • Anthropic gives no cost figure for a normal run. Not confirmed

E. A skill-based deep run in Claude Code

A skill is a set of saved steps that Claude loads when a prompt fits. A research skill splits the work among agents. This guide came from such a run. This session

  1. The lead agent split the question into four parts.
  2. Four agents each took one part. Each wrote notes to a file, with a link for each fact.
  3. One writer agent read the notes and wrote the report.

That run used about 900,000 agent tokens. It had no vote on claims, so it is not the same as the bundled workflow.

Steps

  1. Say "Use the deep-research skill", or let the skill load when the prompt fits.
  2. Give each part a brief with four things: the goal, the output format, the sources to use, and the edges of the task.
  3. Tell agents to mark how they got each fact: read the page, or saw only a search summary.
  4. Have a fresh agent check claims. One user's rule: The agent that finds a claim never verifies it.
  5. Read the report yourself, then check the claims that matter.

The four-part brief comes from Anthropic's June 2025 post. In that post, a short brief made agents repeat the same searches. Vendor

F. The API

Use the API when you need a setting for each search and each fetch.

  1. Start with Opus 5.5. Raise effort before you change the model. Anthropic names Fable 5.2 for multi-step deep research, at twice the price.
  2. Set max_uses to cap the searches in one turn.
  3. Set allowed_domains or blocked_domains. Do not set both, because the API then returns a 400 error.
  4. Turn on citations for web fetch. Search always cites. Fetch cites only if you ask.
  5. If a reply stops with pause_turn, send the assistant message back as it is.
  6. If you show the output to end users, show the citations too. The docs make this a duty.
  • Web search costs $10 for 1,000 searches, plus tokens. Web fetch costs only tokens.
  • Web fetch reads only a link that is already in the chat. It cannot read pages that need JavaScript.
  • Search results count as input tokens in this turn and in later turns.
  • New tool versions filter results with code by default. That mode does not qualify for ZDR or HIPAA.

4. When a plain prompt starts a deep run

A plain prompt can start a deep run. It did in the session that made this guide. The first prompt had no command, and five agents ran. This session

What starts it in Claude Code

  • A skill fits your prompt. This is the main cause. Claude reads each skill's summary and loads the one that fits. Words such as "research", "compare", "best practices" or "report" can start a research skill.
  • Claude starts agents on its own. It can do this for a broad question with parts that stand alone.
  • A high effort level. It makes Claude use more tool calls before it answers.
  • Your own rules. A line in CLAUDE.md or a memory note can ask for a set way to research.

What does not start by itself

  • The bundled workflow. In that session, Claude could start a workflow only if the user asked for one, typed the command, or used a skill that calls for it. This session

In claude.ai

The help page says you start Research with the button or the command. But a normal chat can also run many searches in a row. That can look like Research. No source says if the new claude.ai ever starts Research by itself. Not confirmed

How to pick the path

New models do just what you say. So say which path you want.

5. Write the request

The basic rules did not change in 2026. Be clear, give the reason, name the format, and let Claude say "I don't know". What changed is the control. Depth now comes from the effort setting, not from strong words. Vendor

New models also do less guessing. Anthropic says: If you want Claude to do more than the task strictly requires, explicitly request it rather than relying on the model to infer this from vague prompts.

Ten steps

  1. State the goal and who will read the result.
  2. Describe the output you want. Say when Claude must stop and ask.
  3. Say what a good answer looks like.
  4. Say how deep to go: one fact, a comparison or a broad survey.
  5. Give source rules. Ask for first-hand sources. Name the kinds of sites to skip.
  6. Let Claude say that it does not know.
  7. Ask for a link and an exact quote for each claim.
  8. Use plain words, and give the reason for each rule.
  9. Set the depth with effort. Delete lines such as "think hard".
  10. For a long task, ask for rival ideas and a notes file.

Why each step is there

  • Step 5. In Anthropic's 2025 system, early agents consistently chose SEO-optimized content farms. Source rules in the prompt fixed that. Vendor
  • Step 6. Anthropic says this can drastically reduce false information. It gives no number, date or model for that claim. Vendor
  • Step 9. The Fable 5.2 page says effort sets how much the model thinks, how many tool calls it makes, how long a turn takes, and how many tokens it uses. At low effort, Fable 5.1 searches less and answers from memory more. So the first fix for a thin run is more effort. Vendor

Templates from Anthropic

For step 1, written for Fable 5:

I'm working on [the larger task] for [who it's for]. They need [what the output enables]. With that in mind: [request].

For step 10, for all current models:

Search for this information in a structured way. As you gather data, develop several
competing hypotheses. Track your confidence levels in your progress notes to improve
calibration. Regularly self-critique your approach and plan. Update a hypothesis tree or
research notes file to persist information and provide transparency. Break down this
complex research task systematically.

A full example

This example joins the steps. It is built from the official parts. Nobody tested it as one prompt. Not confirmed

I'm working on a tool decision for a finance team of five people. They need to select
one expense tool this month. With that in mind: compare the current prices and the
export functions of [tool A], [tool B] and [tool C].

6. Check the claims

A link that works proves little. The main error in 2026 is a real page that does not say what the answer claims. It is not a made-up page.

Two things the numbers show
  • Newer was not better. Opus 4.6 scored 54.2 percent. The older Opus 4.5 scored 76.8. A new model is a reason to test again, not a reason to trust more.
  • The proof is older than the product. All Claude data is from Opus 4.6 or before. Opus 5.5 and Fable 5.2 may do better or worse. No source says which.

Anthropic says the same in its own docs: although these techniques significantly reduce hallucinations, they don't eliminate them entirely. Always validate critical information, especially for high-stakes decisions. The help page for Research has no such note. Do not read that as a claim that Research is right. Vendor

Nine check steps, best proof first

  1. Pick the claims your choice rests on. You do not need to check them all.
  2. Open the cited page for each one. Read the part that backs the claim.
  3. Make sure the page is the first source. It must not be a copy, or a page that an AI wrote.
  4. Read the date of the page.
  5. If you do not know the source, search for what others say about it.
  6. Compare each quote with the page, word for word.
  7. For a debated question, ask Claude in a new turn for the best case against its first answer.
  8. Do not count a second AI tool as a check. Go to a first-hand source.
  9. In Claude Code, give the check to a fresh agent that did not find the claim.

How strong is each step?

  • Step 2 has the best proof: the gap between links that work and claims that hold. Independent
  • Step 5 is called lateral reading. A 2025 review pooled 64 trials and found that it helps people judge web sources. The proof is for web pages in general, not for AI answers. Not confirmed
  • Step 6 comes from a BBC study of February 2025. In it, 13 percent of quotes from BBC stories were changed or were not in the story. That study did not test Claude. Not confirmed
  • Steps 7 to 9 have weaker proof. No study measured them for research reports. For step 9, Anthropic says of Fable 5: Separate, fresh-context verifier subagents tend to outperform self-critique. Vendor

Let Claude do a first pass

Anthropic gives this prompt for a press release. Change "press release" to "report".

After drafting, review each claim in your press release. For each claim, find a direct quote from the documents that supports it. If you can't find a supporting quote for a claim, remove that claim from the press release and mark where it was removed with empty [] brackets.

Anthropic made this for documents that you supply. Nobody measured it for web research. A quote that Claude gives back still needs step 6, because a model can change a quote.

What happens with no check

  • On 18 November 2026, one database listed 2,312 court cases that deal with made-up AI content. Independent
  • In May 2025, Anthropic's own outside lawyers told a court that Claude gave a wrong title and wrong authors for a real source. A link check would not have caught it. Not confirmed

7. Gotchas

How Claude reads the web

  • WebFetch gives a summary, not the page. In Claude Code, a second model reads the page and answers a prompt. The docs say: This makes WebFetch lossy by design. So "the page does not say X" is weak proof. Fetch again with a pointed prompt. Vendor
  • WebSearch gives only titles and links in Claude Code. It does not read the pages. Vendor
  • Some pages do not load. The API fetch tool cannot read pages that need JavaScript. An add-on reader can fill that gap, but the only numbers for one come from its seller. Vendor
  • A second search engine may not help. One test compared six search tools, but not with Claude and not with Claude's own search. Its top scores were too close to tell apart. Independent

Cost and limits

  • Agents run on your session model unless you set a smaller one. This is the top cause of a large bill.
  • Claude Code has a limit of 200 searches in one interactive session. Agents share it. You can raise it with CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION. Vendor
  • The big-workflow warning does not stop the run. Watch /workflows yourself.
  • Deep runs use your plan limit faster. Anthropic says so, but gives no number.
  • Context size is seldom the limit now. Most current models hold 1 million tokens. Cost is the reason to use /clear and notes files. Vendor
  • More agents cost more. In June 2025, Anthropic said multi-agent systems use about 15 times the tokens of a chat. That number is from older models. Not confirmed

Where features are missing

  • Research on a phone skips connectors and shows no error.
  • Research cannot use local MCP servers.
  • Amazon Bedrock has no WebSearch, so the bundled workflow does not run there.
  • Research always runs on Opus 5.5, so your model pick has no effect on it.
  • Managed Agents runs the web tools with no search cap and no citation setting. Use the Messages API if you need those.

Hidden instructions in web pages

A web page can hold text that tells Claude to do something. This is called prompt injection. Anthropic says it is far from a solved problem and that No browser agent is immune to prompt injection. Vendor

The danger is highest when three things meet: private data, content you do not trust, and a way to send data out. Research with connectors, a signed-in browser or local files can bring all three together. User report

What to do

  1. In claude.ai, turn off connectors that a web-only task does not need.
  2. In Claude in Chrome, pick "Manually approve".
  3. In Claude in Chrome, use a separate browser profile. Keep bank, health and government accounts out of it.
  4. Stop the task if Claude goes to a site you did not expect, or asks for private data.
  5. In Claude Code, turn on the sandbox and the permission rules together.
  6. Give a research agent only the tools it needs: search, fetch and write.
  7. Block curl and wget, or allow them only in the sandbox with a short list of sites.
  8. Run an agent that works alone in a container or a VM. Keep SSH keys and cloud keys out of it.
  9. Connect only the MCP servers you trust.
  10. Never run a command that a web page told Claude to run.
The sandbox has gaps
  • The docs say: The sandbox covers shell commands only. Claude's file tools, MCP servers, and hooks run outside it.
  • By default, a command in the sandbox can still read key files such as ~/.ssh.
  • A WebFetch block on a site does not block curl to that site, unless the sandbox is on.

Signs that do not prove quality

  • A link that works.
  • A long report or a long source list. DeepTRACE found: More sources and longer answers do not translate into reliability.
  • A paid tier.
  • A sure tone.
  • A second AI tool that agrees. AI tools draw on the same web pages.

Three cases that depend on the model

Self-check lines

  • On Opus 5 and 5.5: remove general lines such as "add a final check step". This covers Research in claude.ai.
  • On Fable 5: make the check explicit in long runs, and use a fresh agent for it.
  • On every model: keep the pointed checks. Ask for more than one source that stands alone. Ask for a quote for each claim. Ask Claude to drop claims with no quote.

Examples in the prompt

  • The general page still says to add 3 to 5 examples.
  • In July 2026, a member of the Claude Code team said that taking examples out helped a lot. That was about a system prompt, not a research prompt. User report
  • What to do: start with no examples. Add one only if the output has the wrong shape.

Strong words

  • The advice says to soften them. But some of Anthropic's own sample prompts still use "MUST" and "IMPORTANT".
  • What to do: copy the structure of those samples, not the tone.

Old advice that still holds

  • A role in the system prompt.
  • Clear and direct asks, with reasons.
  • XML tags to mark parts of a prompt.
  • Documents first, the question last.
  • Quotes before the view.
  • Room to say "I don't know".

  • Anthropic ships a new model.

A habit that helps: keep a few research questions for which you know the right answer. Run them after each model change.
